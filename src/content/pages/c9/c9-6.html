Intuition

People ask questions badly for search engines: "what about contractors?" only makes sense after the previous message, and "compare leave in Germany and the UK" is really two searches. So before searching, rewrite the question into what a search engine needs, split it into parts, or search in steps when one answer leads to the next question.

Then show your working. Every claim gets a citation that can be checked, and if nothing relevant was found, the honest answer is "I could not find that", not a confident guess.

Mechanism

  • Query rewriting: user queries are short, ambiguous or conversational ("what about for contractors?"). An LLM rewrites them into standalone search queries using conversation history, expands acronyms, or generates several variants (multi-query). HyDE generates a hypothetical answer and embeds that instead of the question.
  • Decomposition: split compound questions ("compare the parental leave policies in Germany and the UK") into sub-queries, retrieve for each, then synthesise.
  • Multi-hop retrieval: some answers require a chain: find entity A, then use a fact from A to search for B ("Who approves expenses for the team that owns the billing service?" → find owning team → find its approver). Implemented as an iterative loop, effectively a small agent (10.9, 11).
  • Citations: label chunks, require the model to cite labels per claim, then verify in code that each cited label exists and (with a judge or string overlap) that the cited chunk supports the sentence. Render citations as links to the source.
  • Abstention: when retrieval scores are low or the judge finds no support, say "I couldn't find this in the knowledge base" and offer a next step. A confident wrong answer is worse than an honest "not found".
Example: verifying citations in code
import re
def check_citations(answer: str, chunks: dict[str, str]) -> list[str]:
    problems = []
    for sent in re.split(r"(?<=[.!?])\s+", answer):
        ids = re.findall(r"\[(\d+)\]", sent)
        if not ids and len(sent.split()) > 6: problems.append(f"uncited: {sent[:60]}")
        for i in ids:
            if i not in chunks: problems.append(f"cites missing source [{i}]")
    return problems          # non-empty → regenerate, or show answer with a warning, or abstain

The numbers

What extra steps cost (illustrative). A rewrite by a small model takes about 0.5 seconds; each retrieval about 0.3 seconds. A two-hop answer with a rewrite before each hop adds about 2 × (0.5 + 0.3) = 1.6 seconds before generation even starts, so use it only where evaluation shows single searches fail.

Decomposition doubles the context. Two sub-questions with the top 3 passages each send 6 passages instead of 3. At 500 tokens a passage, that is 3,000 tokens instead of 1,500.

Abstaining is cheaper than being wrong. If a wrong answer to a policy question costs a support follow-up of 20 minutes and an honest "not found" costs 2, an assistant that abstains on 50 hard questions instead of guessing (and getting half wrong) saves about 25 × 20 − 50 × 2 = 400 minutes.
