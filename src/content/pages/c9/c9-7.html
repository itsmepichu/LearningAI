Intuition

Retrieval metrics answer two questions. Did the right passages make it into the shortlist at all? And did they come near the top? A search that puts the answer in position 50 is technically "found", but the model will never see it.

Each metric weighs these differently: recall asks "did we find them?", precision asks "how much junk came with them?", and MRR and nDCG ask "how high up were they?". None of them works without a list of which passages are relevant for each test question.

Mechanism

Relevance labels (qrels): for each test query, which chunks/documents are relevant (binary) or how relevant (graded, e.g. 0–3).
Recall@k: fraction of all relevant items that appear in the top k. The key RAG metric: if the answer chunk is not retrieved, the model cannot use it.
Precision@k: fraction of the top k that are relevant. Low precision wastes context tokens and can distract the model.
MRR (mean reciprocal rank): average over queries of 1/(rank of the first relevant result). Rewards putting a relevant item first.
nDCG@k (normalised discounted cumulative gain): DCG = Σ gain(reli)/log₂(i+1) rewards highly relevant items near the top; divided by the ideal DCG so 1.0 is a perfect ranking. Two gain conventions are common: linear (gain = rel) and exponential (gain = 2rel − 1, which rewards the most relevant items far more). Always state which one you report; the calculator below shows both.

Labels limit every metric. All four metrics assume the relevance labels are complete. An unlabelled but relevant result counts as a miss, which makes a new retriever that finds different (unlabelled) good results look worse than it is. Pooling results from several retrievers before labelling (example below) reduces this bias.

Example: building retrieval labels cheaply

Take 200 real user questions. For each, pool the top 20 results from BM25, dense and hybrid retrievers, and have a subject-matter expert mark relevant chunks (or use an LLM judge, calibrated on 50 human-labelled queries). This "pooled" judgement set lets you compare retrievers fairly. Tools like ranx and BEIR compute the metrics.

Simple, fast keyword retrieval for experiments and hybrid search prototypes.

RAG frameworks

Connectors, chunkers, retrievers and pipelines. Useful for speed; understand the pieces (this chapter) so you can debug them.

The numbers

All four on one query. Two passages are relevant: A (very relevant, grade 3) and B (a little, grade 1). The retriever returns X, A, Y, B, Z.

  • Recall@5: both relevant passages are in the top 5: 2 ÷ 2 = 1.0.
  • Precision@5: 2 of the 5 results are relevant: 2 ÷ 5 = 0.4.
  • Reciprocal rank: the first relevant result is at position 2: 1 ÷ 2 = 0.5.
  • nDCG@5: each position counts less the lower it is (position 1 fully, 2 about 63%, 3 half, 4 about 43%, 5 about 39%). This ranking earns 3 × 0.63 + 1 × 0.43 ≈ 2.32; the best possible order, A then B, would earn 3 × 1 + 1 × 0.63 = 3.63. So nDCG is 2.32 ÷ 3.63 ≈ 0.64.

Moving A to the top would raise the reciprocal rank to 1.0 and nDCG towards 1.0, while recall and precision stay exactly the same.
