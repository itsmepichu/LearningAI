Intuition

An assistant’s notebook has two parts. One page is for the task in hand and is torn out when it is done. The other part keeps things worth remembering: this customer prefers Tamil, reports go to the finance list.

Memories need the same care as any other record. Each says who it belongs to, where it came from and when it expires, a newer fact replaces an older one instead of contradicting it, and nobody else’s notes are ever read out.

Mechanism

  • Short-term (working) state: the current task's messages, tool results, plan and scratch notes. Lives in the context window and in the agent's checkpointed state (11.5). Compact it as it grows (7.5).
  • Persistent memory: facts worth keeping across tasks: user preferences, prior resolutions, learned environment facts ("the staging DB is called stg-eu-2"). Stored as records with source, timestamp, owner and scope.
  • Memory retrieval: fetch relevant memories by semantic search plus filters (same user/tenant), recency and importance scores, then inject the top few into context.
  • Expiration and hygiene: memories go stale or wrong. Give them TTLs, update or supersede instead of piling up contradictions, let users view and delete them, and never store secrets or sensitive data without a policy (16.5). Memory written from untrusted content can be poisoned; record provenance.

The numbers

Scoring a memory (illustrative). One simple score adds three things: words shared with the question, importance and recency.

  • "prefers summaries in English", saved 10 days ago, importance 2: 1 shared word + 0.3 × 2 + (1 − 10 ÷ 365) ≈ 1 + 0.6 + 0.97 = 2.57.
  • "reports go to the finance list", saved 250 days ago, importance 3: 0 + 0.9 + (1 − 250 ÷ 365) ≈ 0.9 + 0.32 = 1.22.

The fresher, matching memory wins. Storage grows. 50,000 users × 40 memories each = 2 million records; with expiry after a year and superseding, far fewer stay live.
