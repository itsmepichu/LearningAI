Intuition

A video game saves your progress at checkpoints. If the power goes out, you restart from the last checkpoint, not from the beginning, and the doors you already opened stay open.

Durable execution does the same for long agent tasks. Each step is saved as soon as it finishes, code allows only certain moves between states, and a restarted worker picks up where the last one stopped instead of repeating what was already done.

Mechanism

Agent tasks can last minutes to days (waiting for approvals, external jobs, rate limits). Processes crash, deploys restart pods, and providers time out. Durable execution means the task's progress survives all of that.

  • Explicit state machine: model the task as states (RECEIVED → INVESTIGATING → AWAITING_APPROVAL → EXECUTING → DONE / FAILED / ESCALATED) with allowed transitions enforced in code. The LLM chooses actions within a state; code controls transitions.
  • Checkpointing: after each step, persist the full state (messages, results, pending actions) keyed by task ID. Agent frameworks (LangGraph checkpointers) and workflow engines (Temporal, which records an event history and replays it) do this.
  • Resumability: on restart, load the last checkpoint and continue. Completed tool calls must not be re-executed; their recorded results are reused.
  • Long-running jobs: release workers while waiting (timers, signals, webhooks) instead of holding threads; time out waiting states with an escalation.
  • Re-check on resume: after a long wait (an approval, a timer, a retry backoff), re-verify that the requester still has access and that business conditions still hold before acting. Execute only the version that was approved.
  • Durable means durable storage: an in-memory checkpointer disappears on restart; use a database-backed checkpointer or a workflow engine. Long tasks return a job ID with a status endpoint and support cancellation instead of holding an HTTP request open.
Example: choosing an engine

A short interactive agent (under a minute) can checkpoint to Postgres after each step via a framework checkpointer. A procurement agent that waits days for approvals and calls slow ERP APIs belongs in a durable workflow engine (Temporal or a cloud equivalent), where each LLM call and tool call is an "activity" with its own retry policy and timeout.

The numbers

How often crashes meet long tasks (illustrative). If a worker restarts on average once a day (deploys, evictions) and a task takes 2 minutes:

  • A day has 1,440 minutes, so a given task has about 2 ÷ 1,440 ≈ 0.14% chance of being interrupted.
  • At 50,000 tasks a day, that is about 50,000 × 0.0014 ≈ 70 interrupted tasks every day.
  • A task that waits 2 days for an approval is interrupted almost certainly, since it spans about 2 restarts.

Without checkpoints those tasks start over, and repeat their earlier side effects.

Code

The program moves your project’s largest case through a state machine, saves a checkpoint after every move, crashes during the write and resumes. The record is read only once. Try moving to a state that is not allowed.
