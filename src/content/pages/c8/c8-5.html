Intuition

When a RAG assistant gives a wrong answer, either it was handed the wrong pages, or it was handed the right pages and still got it wrong. Those need completely different fixes, so measure them separately, like checking whether a student had the right textbook before blaming their reading.

The trick is to give the model the correct pages yourself ("oracle context"). If it answers well then, the problem is finding the pages, not reading them.

Mechanism

Measure each stage separately so you know where a failure comes from.

  • Retrieval evaluation: given a query, did the retriever return the relevant chunks? Needs relevance labels per query; metrics Recall@k, MRR, nDCG (9.7). Independent of the LLM.
  • Answer evaluation: given the retrieved context, is the answer correct, grounded and complete? Evaluate with fixed context too ("oracle context") to separate generation errors from retrieval errors.
  • Agent task evaluation: did the agent achieve the goal in the environment, efficiently and safely? Measured on the trajectory and final state, not just the final message (8.8).
Example

Illustrative numbers. An HR assistant answers 74% of questions correctly. Stage evaluation shows Recall@5 = 79%; with oracle context, answer accuracy is 93%. Most failures are retrieval. Adding hybrid search and a reranker raises Recall@5 to 92% and end-to-end accuracy to 86%, with no LLM change.

The numbers

Retrieval caps everything after it. In the example below, Recall@5 is 79%: for 21% of questions, the right passage never reaches the model. Even with 93% accuracy when it does get the right passage, end-to-end accuracy is at most about 0.79 × 0.93 ≈ 73%, close to the 74% observed.

The fix, in the same numbers. Raising Recall@5 to 92% lifts the ceiling to 0.92 × 0.93 ≈ 86%, which is the end-to-end result reported, with no change to the model at all.

Code

The program builds a query from each of your example project’s document titles, measures Recall@1, 3 and 5 for a simple word-overlap retriever, and shows how retrieval caps end-to-end accuracy. Change ANSWER_ACCURACY_WITH_ORACLE, or make the queries harder by dropping two words, and run it again.
