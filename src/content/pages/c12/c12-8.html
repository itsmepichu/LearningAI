A multi-agent system must beat the strongest simple alternative on the metrics that matter, at acceptable cost. Run the same evaluation set (8.8) through:

  1. a single well-prompted agent with all tools,
  2. a fixed parallel workflow written in code,
  3. the multi-agent design,

and compare task success, pass^k reliability, latency percentiles, cost per successful task, and failure types. Also evaluate components: routing accuracy, worker success per subtask, synthesis faithfulness to worker outputs, and how often conflicts are surfaced correctly. Run ablations: remove the evaluator agent; merge two workers; does quality actually drop?

Example: an ablation that simplified a system

A team removed the critic agent from a four-agent report generator. Task success fell from 81% to 80% (within the confidence interval), latency fell 35% and cost fell 30%. They kept the critic only for reports flagged as high-stakes.

Laptop lab: baseline vs coordinator on one machine Laptop · CPU · slow but workable
import asyncio, ollama
client = ollama.AsyncClient()
DOCS = {"tickets": "...", "sales_notes": "...", "reviews": "..."}      # paste ~1-2k words each
async def ask(prompt, model="qwen2.5:1.5b"):
    r = await client.chat(model=model, messages=[{"role": "user", "content": prompt}], options={"temperature": 0})
    return r.message.content

async def parallel_workflow(q):                                         # decomposition in code
    parts = await asyncio.gather(*[ask(f"From this {k} text, list onboarding complaints with quotes:\n{v}")
                                   for k, v in DOCS.items()])
    return await ask("Merge these findings into the top 5 themes, keep quotes:\n" + "\n---\n".join(parts))

async def single_agent(q):
    return await ask(q + "\n\n" + "\n\n".join(f"## {k}\n{v}" for k, v in DOCS.items()))

q = "What are the top onboarding complaints?"
print(asyncio.run(single_agent(q))); print(asyncio.run(parallel_workflow(q)))
# Score both against a hand-written answer key of themes; repeat 3x; compare tokens and time.

On CPU, parallel calls queue behind each other in one Ollama instance (set OLLAMA_NUM_PARALLEL to allow concurrency; memory use rises), so wall-clock gains are smaller than with a hosted API. The quality and token comparison is still valid.

In practice · HarborHarbor compared one answerer, two workers plus a synthesiser, and a fixed hybrid pipeline on 120 paired tasks; the fixed pipeline matched quality at half the cost and shipped.

Toolbox for multi-agent systems

LangGraph
supervisor · swarm · subgraphs

Multi-agent graphs with explicit state, checkpointing and human-in-the-loop interrupts.

Microsoft Agent Framework
successor to AutoGen + Semantic Kernel

Python and .NET framework for agents and multi-agent workflows (1.0 released). AutoGen is being archived and its README directs new users here.

CrewAI
role-based crews · flows

Define agents with roles and tasks; "flows" add deterministic orchestration around crews.

Google ADK
agent development kit

Code-first agents and multi-agent hierarchies, with evaluation tooling; model-agnostic.

A2A protocol
agent interoperability

Open protocol (Linux Foundation project) for agent discovery and task exchange across frameworks and vendors.

OpenAI Agents SDK
handoffs · agents-as-tools

Simple handoff and agent-as-tool primitives with built-in tracing; good for learning the patterns.
