Intuition

Organisations use a few familiar shapes. A manager splits a project and collects the results (coordinator and workers). A receptionist sends each visitor to the right desk (routing). A support agent transfers a caller to billing, with a note so the caller need not repeat everything (a handoff). An editor reviews a draft and sends it back (evaluator and optimiser).

Agent systems reuse the same shapes, with the same weak points: a busy manager, a visitor sent to the wrong desk, a transfer that loses the note.

Example: handoff with context transfer

A general support agent determines the issue is a disputed charge and hands off to the billing agent. The handoff passes a structured summary (customer ID, issue, evidence collected, what the customer was told) rather than the full transcript, and the billing agent receives only billing tools. The customer sees one continuous conversation.

The numbers

Routing errors add up (illustrative). A router that is 95% right on 10,000 requests a day sends 500 to the wrong specialist.

  • If the router may say "not sure" and send 6% of requests to a general path, and is then 99% right on the remaining 94%: 9,400 × 0.01 = 94 misroutes, and 600 cases handled more slowly.
  • A handoff with a 300-token summary instead of a 6,000-token transcript saves 5,700 tokens per transfer: at 2,000 transfers a day, 11.4 million tokens.

Code

The program learns a simple word-based router from half of your project’s labelled requests, routes the other half, and sends a request to the "other" path when no specialist is clearly ahead. Off-topic requests show why that path is needed. Change the shares in the loop and run it again.
