• Shared state (blackboard): agents read and write a common store (a task board, a document). Easy coordination; risk of conflicting writes, context pollution (everyone sees everything), and permission leakage.
  • Isolated state: each agent has private context and communicates only through messages. Cleaner boundaries and least-privilege data access; requires explicit, well-designed messages.
  • Message contracts: typed, versioned schemas for requests and results (like API contracts between microservices), validated on both ends, including status, errors, confidence and evidence.
  • Interoperability: for agents from different frameworks or organisations, open protocols are emerging. Agent2Agent (A2A) defines agent discovery (agent cards), task lifecycle and message exchange between agents; MCP (11.8) connects agents to tools and data. They are complementary.
Example: a versioned result contract
{"contract": "worker-result/v2", "task_id": "T-17.3", "status": "partial",
 "result": {"themes": [{"theme": "SMS code never arrives", "count": 412, "evidence_ids": ["rv_88", "rv_91"]}]},
 "coverage": {"searched": 9400, "of_estimated": 12000, "reason": "deadline reached"},
 "confidence": "medium", "errors": [], "cost_usd": 0.13}

"status: partial" plus coverage lets the coordinator decide whether to accept, extend the budget, or flag incomplete coverage in the final report.
