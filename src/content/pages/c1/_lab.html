Chapter 1 lab · keep as evidence

Train a tiny language model, then classify five business tasks

  1. Run a real model first. Open the tiny language model in Appendix A, go to Or run it here and press Run. The first run downloads Python and NumPy (about 9 MB), then trains a small character model by counting in a second or two. Write down three numbers from the output: the guessing loss, the unigram baseline and the bigram loss on text the model did not train on. The bigram loss should be the lowest of the three. What this shows: a model that only counts which character follows which beats guessing and beats a baseline that ignores context. What it does not show: anything about how large models behave, because this one sees a single character of context.
  2. Take five tasks from the example project's scenario shown under this lab. If you already work in software, you may use five from your own work instead (for example spotting a missing field, finding a policy, drafting a reply, predicting a delay, summarising a call).
  3. For each, write the input, the expected output, the cost of a wrong answer and the source of truth.
  4. Choose rules, search, traditional ML or an LLM, and write one sentence on why each simpler option fails.
  5. Write ten acceptance examples for the task you would build first, before trying any prompt.
Keep as evidenceThe three loss numbers from step 1, a one-page decision table and ten test cases.
Pass conditionThe bigram loss is below both baselines. Every choice is justified against a simpler alternative; no task is assigned to an LLM without a reason.
