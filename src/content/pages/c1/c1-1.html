Intuition

Think of four boxes, one inside the other. The biggest box, AI, holds every way of making a computer act smart, including rules a programmer types in by hand. Inside it, machine learning is the part where the computer learns the rules from examples instead. Inside that, deep learning learns with large neural networks. And inside that, generative AI uses those networks to create new text, images or code.

A cooking comparison: a recipe card is rules, a cook who learns by tasting many dishes is machine learning, and a cook who can invent a new dish in the same style is generative AI.

Mechanism

These four terms describe nested sets. Each inner one is a particular way of doing the outer one.

Artificial intelligence (AI): any technique that makes a computer perform a task we would call intelligent if a person did it, such as planning, recognising, deciding or conversing. Hand-written rules count.
Machine learning (ML): AI where behaviour is learned from data instead of written by hand. You supply examples; an algorithm fits a function to them.
Deep learning (DL): ML using neural networks with many layers. Layers learn their own intermediate features, so you do not hand-design them.
Generative AI (GenAI): models that produce new content (text, images, audio, code) by learning the distribution of their training data and sampling from it. Today almost all GenAI is deep learning.

The practical difference is where the knowledge comes from. In rule-based AI it comes from the programmer. In classical ML it comes from labelled examples plus features the engineer chose. In deep learning it comes from large amounts of data, and the model chooses the features. In generative AI the model has learned enough about the data to create plausible new samples.

A second difference is the output type. Classical ML typically outputs a number or a label from a fixed set ("fraud: 0.93"). Generative models output open-ended content ("Dear customer, we noticed…"). Open-ended output is more flexible and much harder to verify, which is why evaluation (chapter 8) is so central to GenAI work.

Example: one business problem, four approaches

Routing incoming support emails to the right team:

  • Rules (AI): if "invoice" in subject → Billing. Transparent, brittle when wording changes.
  • Classical ML: TF-IDF word features + logistic regression trained on 20,000 labelled emails. Cheap, fast, accurate on common categories.
  • Deep learning: fine-tuned BERT-style encoder. Handles paraphrase and context better; needs more compute.
  • Generative AI: prompt an LLM with the team descriptions and ask for a label plus a one-line reason. Zero training data needed to start; higher cost per email; must validate that the label is one of the allowed values.

The numbers

What each approach needs before it can start, for the email-routing example above. The prices and times are illustrative.

  • Rules: no data, but someone must write and keep updating every keyword. Twenty rules might take a day to write.
  • Classical ML: labelled examples. Labelling 20,000 emails at 30 seconds each is 20,000 × 30 = 600,000 seconds, about 167 hours of work.
  • Generative AI: no labelled data to start, but every email costs money. With 500 tokens in and 20 tokens out, at $1 per million input tokens and $4 per million output tokens, one email costs 500 × 1 ÷ 1,000,000 + 20 × 4 ÷ 1,000,000 ≈ $0.0006. A million emails a month is about $580.

Running a trained classical model on the same million emails costs only a few dollars of computer time. That gap is why many teams start with an LLM to learn the task and later switch high-volume, stable tasks to a cheaper model.
