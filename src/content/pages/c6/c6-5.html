Intuition

It is often easier to say which of two answers is better than to write the perfect answer yourself. Preference tuning uses that: people (or a strong model) compare pairs of answers, and the model is nudged towards the kind of answer that wins.

There is a catch, like a student gaming a marking scheme. If the scorers secretly like long answers, the model learns to waffle. Where an answer can be checked automatically, such as code that passes its tests or a maths result that is correct, the reward is harder to fool.

Mechanism

Preference data: for one prompt, two or more responses and a judgement of which is better (from humans or a model).
Reward model: a model trained on preference data to output a scalar score for (prompt, response).
RLHF (reinforcement learning from human feedback): generate responses, score them with the reward model, update the policy (the LLM) with an RL algorithm such as PPO to increase reward, with a KL penalty to the original model so it does not drift into exploiting the reward model.
DPO (direct preference optimisation, 2023): skip the reward model and RL loop; a closed-form loss directly increases the probability of the preferred response relative to the rejected one, relative to a frozen reference model. Simpler and more stable; widely used for open models.
RL with verifiable rewards (RLVR): when correctness can be checked automatically (unit tests, maths answers, format rules), use that as the reward. Algorithms like GRPO sample several answers per prompt and reinforce the better-than-average ones. This is how "reasoning" models learn long chains of thought.
Example: a DPO pair

Prompt: "Customer asks for a refund outside the 14-day window." Chosen: polite explanation of the policy plus the escalation option. Rejected: "Sure, refund processed!" (violates policy). Thousands of such pairs teach the model the organisation's preferred behaviour, which is exactly what you can do in chapter 13.

The numbers

GRPO in numbers. The model writes 8 answers to one coding task and 3 pass the tests. The group’s average reward is 3 ÷ 8 = 0.375. Each passing answer gets 1 − 0.375 = +0.625 (make it more likely) and each failing one 0 − 0.375 = −0.375 (make it less likely). No separate reward model is needed.

How a bias becomes reward. In the simulation in the code, raters who are slightly swayed by length produce a reward model that gives the same answer about 2 more points when it is padded from 100 to 400 words. A model optimised against that reward will learn to pad.

Scale. A typical DPO run uses a few thousand to a few hundred thousand preference pairs; the example in the box below needs only enough to cover the behaviours you care about.
