Instruction datasets contain conversations: system prompt, user turns, assistant turns, and increasingly tool calls and tool results. Sources: human-written demonstrations, filtered public datasets, and synthetic data from stronger models (check the licence of the generating model).

A chat template converts a list of messages into the exact token sequence the model was trained on, with special tokens marking roles. Each model family has its own format. Using the wrong template at inference or fine-tuning silently degrades quality. Libraries apply it for you: tokenizer.apply_chat_template(messages).

Loss masking: during SFT you usually compute loss only on assistant tokens. The model should learn to produce answers, not to predict the user's words or the system prompt. Masked positions get label −100 in PyTorch/Hugging Face, which the cross-entropy loss ignores.

Objectives beyond plain next-token cross-entropy include: fill-in-the-middle (for code completion), multi-token prediction, distillation loss (match a teacher model's probability distribution via KL divergence), and preference losses (6.5).

Example: an SFT record
{"messages": [
  {"role": "system", "content": "You extract invoice fields as JSON."},
  {"role": "user", "content": "Invoice #4471 from Acme GmbH, total EUR 1,240.50, due 2026-12-01"},
  {"role": "assistant", "content": "{\"number\":\"4471\",\"vendor\":\"Acme GmbH\",\"total\":1240.50,\"currency\":\"EUR\",\"due\":\"2026-12-01\"}"}
]}
