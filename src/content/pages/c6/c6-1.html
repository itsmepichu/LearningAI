Pretraining: next-token prediction on a huge general corpus. Produces a base model that continues text but does not reliably follow instructions. This stage uses >95% of total compute.
Continued pretraining (domain-adaptive pretraining): more next-token training on domain text (legal, medical, code, a new language) to shift knowledge and vocabulary use.
Supervised fine-tuning (SFT) / instruction tuning: train on curated (instruction, response) conversations so the model learns to act as an assistant.
Preference optimisation: train on comparisons ("response A is better than B") via RLHF or DPO, and increasingly on verifiable rewards (tests pass, maths answer correct) to improve helpfulness, safety and reasoning.
Example: base vs instruct

Prompt "Write a haiku about Kubernetes". A base model may continue: "Write a haiku about Docker. Write a haiku about…" because lists of prompts are common online. The instruct model writes the haiku. Fine-tuning for a narrow format usually starts from the instruct model; continued pretraining usually starts from the base model.

In practice · HarborHarbor uses retrieval for changing policy facts, a small SFT for the mandated answer format, and has not done continued pretraining because evaluation never showed a domain-language gap.
Failure to avoidUsing fine-tuning as a substitute for a permission-aware database of changing facts.
