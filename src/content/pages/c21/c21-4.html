Intuition

Not every parcel needs an express courier. Cost-aware routing sends each kind of request to the cheapest model that still meets its quality bar: a small model for easy classification, a mid-size model for routine answers, the largest only for the hard cases.

Unlike a cascade (20.6), which decides per request after trying the small model, routing decides up front from the request type, so it needs evaluation per type to know which model is good enough where.

Keep the table honest. Re-evaluate each type when models change (18.5), and watch fallback rates: a rising rate means the cheap model no longer meets the bar for that type.

Example: a support mix

A support assistant ran everything on its largest model. Evaluation per request type showed the small model met the bar for "how-to" questions (34% of traffic) and the mid model for billing and access. Routing cut the model bill by about 70% with no drop on the regression suite.

The numbers

Routed cost (illustrative: small 0.0002, mid 0.0015, large 0.006 dollars per request). 1,000 requests: 400 how-to, 450 routine, 150 hard.

  • All on the large model: 1,000 × 0.006 = 6 dollars.
  • Routed: 400 × 0.0002 + 450 × 0.0015 + 150 × 0.006 = 0.08 + 0.675 + 0.90 = 1.655 dollars, about 28% of the cost.
  • If 5% of small-model answers fail a check and fall back to the large model: 20 × 0.006 = 0.12 more.

Code

The program takes the request types and volumes in your project’s labelled data and routes each type to the cheapest model whose illustrative accuracy meets the bar. Raise BAR to 0.94 and watch types move to larger models.
