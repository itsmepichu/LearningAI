Intuition

Ingesting millions of documents is a factory line. Documents arrive, get parsed, cut up, embedded and stored, and each station works at a different speed. Queues between stations act like conveyor belts with storage, so a slow station does not stop the whole line.

Good factories also plan for trouble: a broken item is set aside after a few tries instead of jamming the line, the line slows down at the start when it backs up, and every station keeps a note of how far it got, so after a power cut it carries on instead of starting over.

Mechanism

Queue (Kafka, SQS, Pub/Sub, RabbitMQ): a durable buffer of work items between producers (crawlers, change feeds) and consumers (parse/embed workers). Lets each stage scale and fail independently.
Checkpoint: a durable record of progress (e.g. the connector's last sync cursor, or "document X processed at version 7"), so a crashed job resumes instead of restarting.
Backpressure: when a downstream stage is slower (embedding GPUs saturated, vector DB throttling), upstream stages must slow down instead of overflowing memory or the queue. Implemented with bounded queues, consumer-paced pulling, and rate limits.
Dead-letter queue (DLQ): where items go after exceeding retry limits (corrupt PDF, parser crash), so they do not block the pipeline. Monitor and replay DLQs.
Idempotency: processing the same item twice gives the same result (upsert by chunk ID = hash of doc ID + version + chunk position), so at-least-once delivery is safe.

Out-of-order delivery. Queues redeliver and reorder: an old version's job can finish after a newer one. Guard every write with the source version (compare-and-set: write only if the incoming version is newer than the stored one) so a stale update can never overwrite fresh content. Acknowledge a message only after its result is durably committed, or after a recoverable outbox record exists.

Example: backfill vs live traffic

A new tenant uploads 4M documents while existing tenants edit documents all day. Use two priority lanes: a live lane (edits, deletions; freshness target 5 minutes) and a backfill lane (bulk; best effort). Workers prefer the live lane and fill spare capacity with backfill. Without this, the backfill delays everyone's updates for days.

The numbers

A backlog in numbers. 4 workers at 20 documents a second handle 80 a second. If 90 a second arrive, the backlog grows by 10 every second: 36,000 an hour. Either add a fifth worker or accept that the source falls behind.

Dead letters. If 3% of a million documents are corrupt, 30,000 end up in the dead-letter queue. Without one, each would be retried forever and block real work.

Why idempotency matters. A queue that delivers "at least once" may hand the same document over twice. If each chunk’s id is built from the document, version and position, the second write simply replaces the first, and nothing is stored twice.
