These techniques help specific failure patterns and add cost and complexity. Adopt one only when evaluation shows (a) the failure pattern is common in your queries and (b) the technique fixes it on your benchmark by more than simpler fixes (better parsing, hybrid search, reranking, query rewriting).

Example: evaluation-driven adoption

A team considering GraphRAG labels 300 real queries by type and finds only 6% are multi-hop. On those, GraphRAG improves accuracy from 41% to 63%, but query-decomposition (9.6) with the existing index reaches 58% at a fraction of the cost. They adopt decomposition and revisit graphs if multi-hop traffic grows.

In practice · HarborOnly 6% of Harbor queries were multi-hop; query decomposition fixed most of them, so a knowledge graph was deferred.
Failure to avoidAdopting an advanced retrieval technique because of its name, without a failure analysis showing the gap.

Toolbox for RAG at scale

Docling
document parsing · tables · OCR

Converts PDF, DOCX, PPTX, HTML and images to structured Markdown/JSON with layout and table extraction. CPU OK (slower).

Unstructured · PyMuPDF
partitioning · fast extraction

Element-level partitioning of many formats; PyMuPDF for fast born-digital extraction.

Tesseract
OCR · CPU

Classic open-source OCR engine; good baseline for scanned pages on a laptop.

Apache Kafka
durable queues · streams

Backbone for ingestion events and change feeds; run locally in Docker to practise consumer groups and replay.

PyLate
late interaction (ColBERT)

Train and use ColBERT-style multi-vector models built on Sentence Transformers.

GraphRAG
knowledge-graph RAG

Entity/relation extraction, community summaries, local and global search. Indexing is LLM-call heavy; try on a small corpus.
