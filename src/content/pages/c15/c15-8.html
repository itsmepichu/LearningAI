TestQuestionShape
LoadDo we meet SLOs at expected peak?Ramp to forecast peak, hold 30–60 min
StressWhere and how do we break? Does shedding work?Ramp beyond peak until SLOs fail; observe degradation
SoakLeaks, cache growth, fragmentation, slow degradation?Moderate load for 8–24 h

Realistic distributions matter more for AI than for typical APIs. Prompt and output lengths are heavy-tailed (most short, a few very long); a test with fixed 500-token prompts underestimates KV-cache pressure and tail latency. Replay sampled production traces (lengths, tenants, features, cache-hit rates), use realistic arrival processes (bursty, not evenly spaced), and include agent sessions with many sequential calls. For hosted APIs, test against a mock that reproduces latency distributions and rate limits, so load tests do not cost a fortune or hit provider limits.

Open vs closed loop. A closed-loop tester (N virtual users, each waiting for its response before sending the next) slows down when the service slows down, so it under-reports latency: this is called coordinated omission. An open-loop tester sends requests at a set arrival rate regardless of responses (k6's ramping-arrival-rate executor in the lab below), which exposes queue build-up. Tests against a mocked model validate orchestration, queues and gateways only; real model-serving capacity needs its own benchmark (14.7).

Laptop lab: load-test a mock LLM endpoint with k6 Laptop · CPU
// mock: a tiny server that sleeps TTFT + n_tokens*ITL and streams (write one in FastAPI), or point at llama-server
// loadtest.js  — run with:  k6 run loadtest.js
import http from 'k6/http'; import { check } from 'k6';
export const options = { scenarios: { ramp: { executor: 'ramping-arrival-rate', startRate: 2, timeUnit: '1s',
  preAllocatedVUs: 200, stages: [{ target: 20, duration: '2m' }, { target: 20, duration: '5m' }, { target: 60, duration: '2m' }] } },
  thresholds: { http_req_duration: ['p(95)<8000'], http_req_failed: ['rate<0.01'] } };
const lens = [80, 120, 200, 400, 900, 3000];                     // crude heavy-tailed mix
export default function () {
  const n = lens[Math.floor(Math.random() ** 2 * lens.length)];
  const r = http.post('http://localhost:8080/v1/chat/completions', JSON.stringify({
    messages: [{ role: 'user', content: 'x '.repeat(n) + 'Summarise.' }], max_tokens: 64 }),
    { headers: { 'Content-Type': 'application/json' }, timeout: '30s' });
  check(r, { 'status 200': (x) => x.status === 200 });
}

Limitation: your laptop is both load generator and server, so absolute numbers mean little. The point is to practise realistic scenarios, thresholds and reading percentile output.
