• Stateless services: request handlers keep no session in memory, so any replica can serve any request and replicas can be added or killed freely. Conversation state lives in a database (7.5); streaming connections can resume by response ID.
  • Durable state: conversations, agent checkpoints, tasks, usage records and audit logs in replicated databases with backups. Choose stores per access pattern (Postgres for transactional state, object storage for documents, a vector store for embeddings).
  • Queues: anything that need not finish within the user's request (document processing, long agent tasks, batch summarisation, evaluation) goes through a queue with workers, giving retries, backpressure and smoothing of peaks.
  • Caches: exact-match response cache (same normalised request → stored answer; safe for deterministic, non-personal queries); semantic cache (similar query embedding → stored answer; risky: similar is not identical, so restrict to FAQ-style content and include tenant and permission scope in the key); retrieval cache (query → chunk IDs); prefix/KV cache in the model server (14.3). Every cache needs invalidation tied to document updates (10.4).
  • Asynchronous UX: for tasks over ~30 s, return a task ID immediately, show progress, and notify on completion, rather than holding an HTTP connection open.
Example: a semantic cache incident

"How do I cancel my subscription?" and "How do I cancel my colleague's subscription?" are 0.94 cosine-similar. A semantic cache with threshold 0.92 served the first answer to the second question, which required an admin role. Fix: scope semantic caching to a curated FAQ set, raise the threshold, and include role in the cache key.
