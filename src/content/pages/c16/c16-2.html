Intuition

A model cannot reliably tell the difference between instructions from you and instructions that happen to be inside the text it reads. So a sentence hidden in a review, an email or a web page can try to take over: prompt injection.

Filters catch many attempts, but attackers rephrase. The dependable defence is architectural: decide what a manipulated model could do, and make sure the answer is "nothing harmful". Read-only tools while reading untrusted text, approvals for writes, and no unapproved ways to send data out.

Mechanism

  • Direct prompt injection: the user types instructions to override the system prompt ("ignore your rules and…"). Jailbreaks are injections aimed at safety policies.
  • Indirect prompt injection: instructions hidden in content the model reads: a web page, an email, a PDF (even in white text or metadata), a code comment, a tool description or tool output. The user may be the victim, not the attacker.
  • Data exfiltration: getting data out through any channel the model can influence: URLs in links or images, tool calls that send messages or make HTTP requests, or simply the answer shown to an attacker-controlled account.
  • Poisoned content: false facts planted in the knowledge base or in training data so the model confidently repeats them; also memory poisoning in agents (11.4).
  • Unsafe tool execution: the model calls powerful tools with attacker-chosen arguments (deleting records, sending money, running shell commands).

There is no complete defence at the model level today: classifiers and careful prompting reduce success rates but do not eliminate them. Defence is architectural: limit what a manipulated model can do (capabilities, permissions, approvals, egress), so a successful injection has little impact.

Example: layered controls for an email assistant
  • Untrusted email bodies are passed as data in delimited blocks, never in the system message.
  • The model's tools while processing untrusted content are read-only; send_email requires a user click showing recipient and content.
  • Outbound recipients outside the organisation trigger a warning; links and images in output are restricted to an allowlist of domains.
  • An injection classifier flags suspicious content for logging and lower trust, and red-team cases (8.6) cover the pattern.

The numbers

Filters reduce, they do not remove (illustrative). 10,000 injection attempts a month against a filter that catches 95% still leaves 500 that reach the model.

  • If the model has a send tool while reading them and follows 1 in 20, that is 25 attempts a month that can act.
  • If the tools available while reading untrusted content are read-only, the same 500 attempts can at worst produce a bad draft that a person reviews.

False alarms cost too. A filter that flags 2% of 1 million ordinary messages wrongly blocks 20,000 customers.
