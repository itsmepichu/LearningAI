• Red teaming: deliberately attacking your system (not just the model) before attackers do: injections via every content source, jailbreaks, data extraction, cross-tenant probes, tool abuse, cost attacks (inputs designed to maximise tokens). Combine automated scanners (garak, PyRIT, promptfoo red-team) with human creativity; feed findings into regression suites (8.6).
  • Policy enforcement: write the policy (what the system must not do or say) and enforce it with layered controls: input/output classifiers (e.g. Llama Guard-style safety models), rules, guardrail frameworks, and architectural limits. Measure each control's catch rate and false-positive rate.
  • Human oversight: approvals for consequential actions (11.7), review queues for flagged outputs, the ability to stop an agent or disable a feature quickly (kill switches and feature flags), and clear accountability for each AI system.
  • Incident response: AI incidents include data leaks, harmful outputs at scale, runaway costs, injection-driven actions and quality collapses. Prepare runbooks (17.8), preserve traces as evidence, contain (disable tool, roll back prompt/model, block source), notify per legal obligations, and run a blameless postmortem.
Laptop lab: scan a local model with garak Laptop · CPU · slow
pip install garak
# probes for prompt injection and related weaknesses against a local Ollama model
python -m garak --target_type ollama --target_name llama3.2:1b --probes promptinject
python -m garak --list_probes          # explore other probe families

Small models fail many probes; the exercise is to read the report, understand each probe family, and then design system-level mitigations, since swapping the model alone will not fix architectural exposure. Older garak versions used --model_type/--model_name; current versions use --target_type/--target_name.
