• Model licences: "open-weight" does not mean open-source. Licences vary: permissive (Apache-2.0, MIT), custom community licences with usage restrictions or user-count thresholds, non-commercial research licences, and terms that restrict using outputs to train other models. Legal review per model, recorded in a model inventory.
  • Dataset licences and provenance: know where training, fine-tuning and evaluation data came from, under what licence and consent, and whether it contains personal data. Synthetic data inherits restrictions from the model that generated it.
  • Model supply chain: weights from public hubs can be tampered with or backdoored. Python pickle-based checkpoint formats can execute arbitrary code on load; prefer safetensors, avoid trust_remote_code=True unless the code is reviewed and pinned, scan artefacts (e.g. ModelScan), pin to exact revisions (commit hashes), and mirror approved models in an internal registry.
  • Software supply chain: AI stacks pull many fast-moving dependencies (engines, CUDA libraries, agent frameworks, MCP servers). Use lockfiles, vulnerability scanning, SBOMs, signed artefacts (Sigstore/cosign), and provenance attestations (SLSA). An AI-BOM extends the SBOM with models, datasets and their versions.
Example

A team loads a fine-tuned model from a personal hub account using trust_remote_code=True. The repository's custom modelling file contains code that reads environment variables and posts them to a remote server. Intake policy would have blocked it at the "scan" step; runtime egress restrictions would have blocked the exfiltration.
