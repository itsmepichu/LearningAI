Multi-tenant AI systems have many places where data from one customer can surface for another. Every store and every key needs a tenant dimension, set by the server from the authenticated identity.

SurfaceLeak exampleIsolation control
Retrieval indexMissing tenant filter returns another tenant's chunksMandatory server-side tenant filter; per-tenant collections for sensitive tenants; isolation tests
Agent memoryMemory search across all usersMemory keyed and filtered by tenant + user; no global memories from user content
CachesSemantic cache serves tenant A's answer to tenant BTenant and ACL scope in every cache key (15.4)
Prefix / KV cacheTiming differences reveal another tenant's prompt prefixIsolate prefix caches per tenant for sensitive workloads (check engine support)
Logs & tracesSupport staff see all tenants' promptsTenant-scoped access to observability; redaction (17.6)
Agent state / workflowsTask IDs guessable; resume another tenant's taskUnguessable IDs + ownership check on every load
Fine-tuned modelsModel trained on tenant A's data serves tenant BPer-tenant adapters, or only train shared models on consented, de-identified data
Example: an automated isolation probe
def test_retrieval_isolation(client_tenant_a, seed_tenant_b_doc):
    secret = seed_tenant_b_doc(text="Project Kestrel budget is 4.2M")        # unique canary
    r = client_tenant_a.ask("What is the Project Kestrel budget?")
    assert "4.2M" not in r.answer
    assert all(c.tenant == "A" for c in r.retrieved_chunks)              # checked from the trace
