Intuition

The context window is a suitcase with a weight limit. Everything the model needs for this one answer has to go in: the instructions, the tools, the customer’s details, the relevant documents, the recent conversation, and room for the answer itself. Packing it is a skill.

Pack the essentials first, then the most useful extras, and fold big items smaller (summaries, trimmed passages) when space runs out. Overpacking hurts too: a stuffed suitcase is slow, expensive, and makes it harder to find what matters.

Mechanism

Context engineering is deciding, for every model call, exactly which tokens go into the window. The model only knows what is in context, and the window is a budget shared by instructions, tools, history, retrieved documents and the output. Too little context and the model guesses; too much and it gets slower, costlier and more distracted by irrelevant material.

  • Assemble from sources: system prompt, tool definitions, user profile, conversation history, retrieved chunks, scratchpad/agent state.
  • Prioritise: rank pieces by necessity (instructions, current question) and relevance score; drop lowest first.
  • Compress: summarise old turns, trim documents to relevant passages, remove duplicate chunks, replace long tool outputs with extracted key fields.
  • Order: important material near the start or end; models attend less reliably to the middle of very long contexts.
  • Reserve output tokens: the budget must include max output length.
Example: a support assistant's context recipe

System prompt (900 tokens, always) → tool schemas (600, always) → customer's plan and open incidents (200, always) → top 5 reranked help-centre chunks (≈ 2,500, drop from the bottom if needed) → summary of conversation so far (300) → last 4 turns verbatim (≈ 800) → current question. Output reserve 800 tokens. Total ≈ 6,100 of a 16k window: faster and cheaper than filling it.

The numbers

The support assistant’s recipe, added up (from the example above):

PartTokens
System prompt + tool schemas + customer details900 + 600 + 200 = 1,700
Five help-centre passagesabout 2,500
Summary + last 4 turns + question300 + 800 + 100 = 1,200
Reserved for the answer1,000
Total6,400

At $1 per million input tokens, the 5,400 input tokens cost about half a cent per question. Sending the whole 40-turn conversation and 20 passages instead could easily triple that, and make the answer slower and less focused.

Code

The program ranks your example project’s documents against one question, then fills a token budget greedily by priority: essentials first, then documents in order of relevance, trimming or dropping what does not fit. Change WINDOW or RESERVE_FOR_ANSWER and watch what gets dropped.
