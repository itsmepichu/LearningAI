Intuition

A model cannot read letters or words directly; it reads numbers from a fixed list. If the list held every word, it would never be finished: typos, new product names and other languages keep arriving. If it held only single characters, every sentence would be very long and slow to process. Subword tokenisation sits in between: common words get one entry each, and rare words are spelled out from smaller pieces that are in the list.

Think of it as a shorthand learned from one stack of documents. The shorthand is excellent for text like that stack and clumsy for anything else, which is why the same message can cost very different amounts in different languages.

Mechanism

Byte-pair encoding (BPE) learns the vocabulary from a corpus: start with individual characters (or bytes), count every adjacent pair, merge the most frequent pair into a new token, and repeat until the vocabulary reaches its target size. At tokenisation time, the learned merges are applied in the same order. Byte-level BPE starts from the 256 byte values, so any text, including emoji and unseen scripts, can be encoded with no "unknown" token. Other algorithms (WordPiece, Unigram/SentencePiece) differ in how they choose merges but have the same effect.

Multilingual implications. Tokenisers are trained mostly on English-heavy data, so other languages often need more tokens for the same meaning. More tokens means higher cost, slower responses, and less content fitting in the context window. Some scripts (e.g. Thai, Amharic, Burmese) can need several times more tokens than English on older tokenisers. Newer models with larger vocabularies (100k–260k tokens) reduce but do not eliminate the gap. Always measure token counts on your real languages before estimating cost.

Example: why models miscount letters

"How many r's in strawberry?" The model may see tokens like str·aw·berry, never individual letters. Counting requires knowledge it learned indirectly about spelling. Tasks that depend on characters (counting, reversing, exact string edits) should be done in code, with the LLM calling a tool (7.4).

The numbers

One BPE step. Look at every pair of neighbouring pieces in every word, and count how often each pair appears. A word that appears 10 times in the text counts 10 times. The pair with the highest count is merged into one new piece, and that piece is added to the vocabulary.

Vocabulary size. Every merge adds exactly one token. Byte-level BPE starts with 256 tokens (one per byte), so 50,000 merges give 50,256 tokens. GPT-2 did exactly this and added one special end-of-text token: 50,257 in total.

The token tax. Take the same message in two languages and count the tokens in each. Divide the other language's count by the English count:

  • English: 100 tokens. Tamil: 240 tokens. The tax is 240 ÷ 100 = 2.4.
  • The Tamil conversation costs about 2.4 times as much.
  • It also fits only 100 ÷ 240 ≈ 42% as much text into the same context window.
