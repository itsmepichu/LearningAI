Intuition

To understand a word you look at the words around it, and some neighbours matter much more than others. In "The server that crashed restarted", the word "restarted" needs to find its subject, "server", and can mostly ignore "that". Attention is how a transformer does this: every token asks a question, every token advertises what it holds, and each token collects a blend of the others, weighted by how well they answered its question.

It works like a soft lookup in a dictionary. A normal lookup returns the one entry whose key matches exactly; attention returns a weighted mix of all entries, with the closest matches weighted most.

Mechanism

Query (Q), Key (K), Value (V): three vectors computed from each token's representation by learned matrices WQ, WK, WV. Intuition: the query says "what I am looking for", the key says "what I contain", the value is "what I will pass on".
Attention: each token's output is a weighted average of all values, weighted by how well its query matches each key. The numbers part below works through an example.
Self-attention: Q, K and V all come from the same sequence. Cross-attention: Q comes from one sequence (the decoder) and K, V from another (the encoder's output), as in translation.
Multi-head attention: run several attentions in parallel with different learned projections (e.g. 32 heads of dimension 128), then concatenate. Different heads learn different relations (syntax, coreference, position).
Causal mask: in a generator, token i may only attend to tokens ≤ i. Scores for future positions are set to −∞ before softmax, so their weight is exactly 0.
Example: what attention resolves

In "The server that crashed restarted", the verb "restarted" needs its subject. A trained head may put high weight from "restarted" onto "server", skipping "crashed". The output vector for "restarted" then contains information about the server, which later layers use to predict the next token (e.g. "at", "after").

The numbers

A small worked example. Take the token "restarted". Its query is compared with the key of every earlier token, giving one score each. The scores here are illustrative:

TokenScoreAfter softmax (weight)
server40.84
that10.04
crashed20.11

Softmax turns the scores into weights that add up to 1 (5.5 shows how). The output for "restarted" is then 84% of the value of "server", 4% of "that" and 11% of "crashed", added together. So it mostly carries information about the server.

Why scores are divided by the square root of the width. A score is the sum of one multiplication per dimension, so wider vectors give bigger scores. With very big scores, softmax gives almost all the weight to one token and learning stalls. Dividing by the square root of the width brings scores back to a normal size: for 128 dimensions that is about 11.3, so a raw score of 45 becomes about 4.

The cost. Every token is compared with every token, so each head builds a table of tokens × tokens scores:

  • 1,000 tokens: 1,000 × 1,000 = 1 million scores.
  • 2,000 tokens: 4 million scores. Double the text, four times the work (5.7).
