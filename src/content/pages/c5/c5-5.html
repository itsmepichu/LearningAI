Intuition

An LLM does one thing over and over: given the text so far, it scores every token in its vocabulary for how well it would fit next. The scores become probabilities, one token is chosen, it is appended to the text, and the whole step repeats. A long answer is thousands of these small guesses in a row, like predictive text on a phone, run with a far better model.

Training uses the same step in reverse: show the model real text, and nudge it to give more probability to the token that really came next.

Mechanism

Logits: raw, unbounded scores the LM head outputs, one per vocabulary token. Higher = more likely.
Softmax: converts logits to probabilities that are positive and sum to 1. Adding a constant to all logits changes nothing; only differences matter.
Autoregressive: each output token becomes part of the input for the next step. Generation is inherently sequential: token 50 cannot be computed before token 49.

Two phases matter for performance. Prefill processes the whole prompt in one parallel pass (fast per token). Decode then produces one token per forward pass (slow per token). To avoid recomputing keys and values for earlier tokens at each step, engines store them in the KV cache (14.1).

The numbers

The probability of a whole sentence is the probabilities of its tokens multiplied together. If the model gives "The" 0.2, then "cat" 0.1, then "sat" 0.3, the whole phrase gets 0.2 × 0.1 × 0.3 = 0.006.

Softmax in three steps. Raise the number e (about 2.718) to the power of each score, add the results, and divide each by the total. The example below does this by hand. Adding the same number to every score changes nothing: the scores [12, 11, 10.1] give the same probabilities as [2, 1, 0.1].

Example: softmax by hand

Logits for three tokens: [2.0, 1.0, 0.1]. e2 = 7.39, e1 = 2.72, e0.1 = 1.11, total 11.22. Probabilities: 0.66, 0.24, 0.10. If the true next token is the second one, its cross-entropy loss is −ln(0.24) = 1.42.

The training loss. For each position, take the probability the model gave to the token that really came next, and take minus its natural log (the cross-entropy, 2.4). A confident right answer costs little and a confident wrong one costs a lot:

A model that guesses evenly across a 128,000-token vocabulary scores a loss of about 11.8, so training starts near there and goes down.

Code

The program builds the smallest possible language model from your example project's English messages: a bigram model whose logit for the next word is the log of how often it followed the current word. It prints the top candidates with their probabilities, generates greedily, and measures its loss on messages it did not train on, next to the loss of an even guess. Change the smoothing value 0.1 to 1.0 and watch the held-out loss and the probabilities change.

Laptop lab: look at real logits Laptop · CPU
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM
name = "HuggingFaceTB/SmolLM2-135M"                      # 135M params, ~270 MB, fast on CPU
tok = AutoTokenizer.from_pretrained(name); model = AutoModelForCausalLM.from_pretrained(name)
ids = tok("The capital of France is", return_tensors="pt").input_ids
with torch.no_grad(): logits = model(ids).logits[0, -1]     # scores for the next token
probs = torch.softmax(logits, -1); top = torch.topk(probs, 8)
for p, i in zip(top.values, top.indices): print(f"{p:.3f}  {tok.decode(i)!r}")
out = model.generate(ids, max_new_tokens=12, do_sample=False)  # greedy autoregressive loop
print(tok.decode(out[0]))
