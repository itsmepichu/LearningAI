• Greedy: always take the most probable token. Deterministic in principle; can be repetitive.
  • Temperature T: divide logits by T before softmax. T < 1 sharpens the distribution (more predictable), T > 1 flattens it (more varied, more errors). T → 0 approaches greedy.
  • Top-k: keep only the k most probable tokens, renormalise, sample.
  • Top-p (nucleus): keep the smallest set of tokens whose cumulative probability reaches p (e.g. 0.9), renormalise, sample. Adapts to how confident the model is.
  • Stop conditions: end-of-sequence token, a maximum number of new tokens, or stop strings (e.g. "\n\nUser:"). Always set a max token limit; it bounds cost and latency.
  • Other controls: repetition/frequency penalties, min-p, and constrained decoding to force valid JSON (7.4).

Filter order varies by engine. Engines differ in the order they apply temperature, top-k, top-p, min-p and penalties, and in whether they renormalise between steps, so identical settings can give different distributions on different engines. The demo below applies temperature first, then top-k and top-p together. Check your engine's documentation before comparing settings across providers.

Reproducibility limits. Even with temperature 0 and a fixed seed, outputs can differ between runs. Causes include floating-point non-associativity on GPUs (summing in a different order gives slightly different results), batching with other requests changing kernel choices, different hardware or library versions, and silent model updates by providers. Tiny numeric differences can flip a near-tie between two tokens, and the texts then diverge. Design tests to check properties ("valid JSON", "mentions clause 4.2") rather than exact strings, and pin model versions.

Example: settings per use case

Data extraction into JSON: temperature 0, constrained schema, max 500 tokens. Customer reply drafting: temperature 0.5–0.7, top-p 0.9, stop at signature. Brainstorming product names: temperature 1.0, sample several candidates and rank them. Reasoning models often recommend specific settings; check the provider documentation, as some ignore or restrict these parameters.
