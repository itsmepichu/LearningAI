Intuition

Quantisation is like saving a photo at lower quality: the file is smaller and loads faster, and most of the time you cannot tell, until you zoom in on the hard parts. For a model, the hard parts are long contexts, maths, code and less common languages.

Speculative decoding is a fast junior who drafts the next few words and a senior who checks them all at once, keeping the ones they agree with. When the text is predictable, the senior signs off several words per look, and the answer is exactly what the senior alone would have written.

Mechanism

  • Weight quantisation (gains depend on kernels and hardware; a format your GPU lacks fast kernels for can be slower): store weights in 8, 4 or fewer bits. Methods: FP8 (hardware-supported on recent GPUs, near-lossless), INT8, 4-bit methods such as GPTQ and AWQ (calibrated on sample data), and llama.cpp's GGUF k-quants (Q4_K_M, Q5_K_M, Q8_0) for CPU and Apple silicon. Smaller weights mean less memory and faster decode (fewer bytes read per token).
  • Activation and KV-cache quantisation: FP8 KV cache doubles capacity; W8A8 quantises both weights and activations to use INT8/FP8 matrix units for faster prefill.
  • Quality cost: usually small at 8-bit, noticeable on hard tasks at 4-bit for small models, larger at 2–3 bits. Long-context, maths, code and non-English often degrade first. Always evaluate the quantised model on your task suite rather than trusting perplexity.
  • Speculative decoding: a small fast draft model (or extra prediction heads, as in Medusa/EAGLE, or n-gram lookup) proposes k tokens; the large target model verifies all k in one forward pass and accepts the longest correct prefix, plus one token of its own. Output distribution is mathematically the same as the target model's. Speeds up decode when acceptance rates are high (predictable text, code) and batch sizes are small.
  • Other compression: distillation into smaller models (13.1), pruning (removing weights or whole layers/heads), and smaller vocabularies or shorter outputs.

The numbers

Smaller weights. An 8B model in 16-bit is 8 × 2 = 16 GB; in 8-bit 8 GB; in 4-bit about 4.5 GB. Decode reads all weights for every token, so 8-bit could at best be 2× faster and 4-bit about 3.5×; real gains are lower.

Speculative decoding with 4 draft tokens and 80% acceptance. The first draft token is accepted 80% of the time, the second 80% × 80% = 64%, then 51% and 41%. Add the target’s own token: 1 + 0.8 + 0.64 + 0.51 + 0.41 ≈ 3.4 tokens per target pass instead of 1. At 50% acceptance it is only 1 + 0.5 + 0.25 + 0.13 + 0.06 ≈ 1.9.

Code

The program simulates draft-and-verify rounds for three draft lengths and three acceptance rates and compares the tokens per target pass with the expected value, then sizes an 8B model in three formats. Change the acceptance rates and run it again.

Laptop lab: quantisation on CPU with llama.cpp Laptop · CPU
# Download two GGUF quantisations of the same small model from Hugging Face (e.g. Q8_0 and Q4_K_M of a 1–3B model)
llama-bench -m model-Q8_0.gguf   -p 512 -n 128      # pp512 = prefill tok/s, tg128 = decode tok/s
llama-bench -m model-Q4_K_M.gguf -p 512 -n 128
llama-perplexity -m model-Q4_K_M.gguf -f wiki.test.raw   # quality proxy; then run YOUR eval set too

Expect decode (tg) to be noticeably faster for Q4 than Q8 while prefill (pp) changes less: decode is bandwidth-bound, prefill is compute-bound. llama.cpp also supports speculative decoding with a draft model in llama-server (-md); check the current flags in its README.
