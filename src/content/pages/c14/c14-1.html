Intuition

A GPU’s memory is a desk. The model’s weights take up a fixed part of it, shared by everyone. What is left holds each conversation’s notes, the KV cache, which grow with every token read or written.

So the number of people one GPU can serve at once depends mostly on how long their conversations are. Long contexts are expensive not because of the model, but because their notes fill the desk.

Mechanism

  • Weights: parameters × bytes per parameter (2.6). Loaded once, shared by all requests.
  • KV cache: for every token in every active sequence, each layer stores its key and value vectors so they are not recomputed (5.5). Bytes per token = 2 (K and V) × layers × KV heads × head dimension × bytes per value. It grows with context length × number of concurrent sequences, and is usually what limits how many users one GPU can serve.
  • Activations: temporary tensors during a forward pass; modest at inference, larger during long prefills.
  • Overhead: CUDA context, framework buffers, CUDA graphs, fragmentation. Engines typically reserve a fraction (e.g. 90%) of GPU memory and use whatever remains after weights for KV cache.

Grouped-query attention (GQA) shares each KV head across several query heads (e.g. 32 query heads, 8 KV heads), cutting KV cache by 4× with little quality loss. That is why modern models list "KV heads" separately.

Example: one 80 GB GPU, 8B model in BF16

Weights 16 GB; overhead ~8 GB; leaves ~56 GB for KV. At 128 KiB per token (BF16, GQA with 8 KV heads), that holds ~427,000 tokens: about 52 concurrent conversations of 8k tokens, or 3 of 128k. Switching the KV cache to FP8 doubles that.

The numbers

KV cache per token for an 8B model with 32 layers and 8 KV heads of 128 numbers, in 16-bit (2 bytes):

  • Keys and values: 2 × 32 layers × 8 heads × 128 numbers × 2 bytes = 131,072 bytes = 128 KiB per token.
  • One 8,000-token conversation: 8,000 × 131,072 bytes ≈ 1.05 GB.
  • One 80 GB GPU: 16 GB of weights and about 8 GB of overhead leave about 56 GB, so about 56 ÷ 1.05 ≈ 53 conversations of 8,000 tokens, or 3 of 128,000.

Storing the cache in 8-bit halves the bytes per token and doubles those numbers.
