Batching more sequences together raises throughput (total tokens/s per GPU) because the weight read is shared, but each step takes longer, so per-user latency rises. At some batch size the GPU becomes compute-bound and throughput plateaus while latency keeps growing. The operating point is chosen by the SLO: "maximise tokens/s subject to p95 ITL ≤ 50 ms and p95 TTFT ≤ 1 s".

Admission control protects that operating point: cap concurrent sequences per replica (e.g. vLLM max_num_seqs) and KV usage, queue extra requests with a bounded queue, reject or redirect when the queue's expected wait exceeds the deadline (15.6), and prioritise interactive traffic over batch.

GPU utilisation metrics need care: "GPU utilisation 100%" from nvidia-smi only means a kernel was running, not that compute units were busy. Prefer tokens/s, model FLOPs utilisation (MFU) for prefill, memory-bandwidth utilisation for decode, KV-cache usage and batch size.
