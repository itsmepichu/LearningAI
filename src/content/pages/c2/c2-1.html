Intuition

A vector is a list of numbers, and you can picture it as an arrow. AI turns words, sentences and images into these arrows so that things with similar meaning point in similar directions. "Invoice" and "bill" point almost the same way; "giraffe" points somewhere else.

To compare two arrows, you check how much they point the same way, like two people pointing at the same building from different distances. Searching for similar documents then becomes "find the arrows pointing closest to my question's arrow".

Mechanism

Vector: an ordered list of numbers, e.g. [0.2, −1.3, 0.7]. Geometrically, an arrow in space. An embedding is a vector with hundreds or thousands of entries (its dimensions).
Matrix: a grid of numbers with rows and columns. Multiplying a vector by a matrix transforms it (rotates, stretches, projects). A neural network layer is mostly a matrix multiplication.
Dot product a·b = Σ aᵢbᵢ. Large when vectors point the same way. Norm ‖a‖ = √(a·a), the vector's length.
Cosine similarity = a·b / (‖a‖‖b‖), the cosine of the angle between them: 1 = same direction, 0 = unrelated (perpendicular), −1 = opposite.
Projection of a onto b: the shadow of a along b's direction, (a·b/‖b‖²)·b. It answers "how much of a points along b?"

Why this matters: an embedding model maps text to vectors so that related meanings point in similar directions. Retrieval then becomes "find the stored vectors with the highest cosine similarity to the query vector". If vectors are normalised (scaled to length 1), cosine similarity equals the dot product, which is cheaper to compute, so vector databases usually normalise.

A matrix multiply y = W·x computes many dot products at once: each output entry is the dot product of one row of W with x. A transformer layer with a 4096×4096 weight matrix does 16.7 million multiply-adds per token for that one matrix. This is why AI hardware is designed around fast matrix multiplication.

Example: three tiny "embeddings"

Suppose "invoice" = [0.9, 0.1, 0.2], "bill" = [0.8, 0.2, 0.3], "giraffe" = [0.1, 0.9, 0.1]. cos(invoice, bill) = (0.72+0.02+0.06)/(0.93·0.88) ≈ 0.98; cos(invoice, giraffe) = (0.09+0.09+0.02)/(0.93·0.91) ≈ 0.24. A search for "bill" therefore retrieves documents about invoices even though the word differs.

Laptop lab Laptop · CPU
import numpy as np
E = np.array([[0.9,0.1,0.2],[0.8,0.2,0.3],[0.1,0.9,0.1]])   # rows = vectors
E = E / np.linalg.norm(E, axis=1, keepdims=True)              # normalise
print(np.round(E @ E.T, 3))          # all pairwise cosine similarities in one matrix multiply
q = np.array([0.85,0.15,0.25]); q /= np.linalg.norm(q)
print(np.argsort(-(E @ q)))          # brute-force "vector search": rank rows by similarity

The numbers

Same direction, different length. Take a = [3, 4] and b = [6, 8]. b is a twice as long.

  • Dot product: multiply matching numbers and add them up: 3 × 6 + 4 × 8 = 18 + 32 = 50.
  • Lengths: a is 5 long (a 3-4-5 triangle) and b is 10.
  • Cosine similarity: 50 ÷ (5 × 10) = 1. The arrows point exactly the same way.

Now c = [4, −3]: 3 × 4 + 4 × (−3) = 12 − 12 = 0, so a and c are at a right angle: unrelated.

Why GPUs matter. One 4,096 × 4,096 weight matrix applied to one token is 4,096 × 4,096 ≈ 16.8 million multiply-and-add steps. An 8-billion-parameter model does about 2 × 8 billion = 16 billion operations for every token it reads or writes.
