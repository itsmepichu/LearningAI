Intuition

When a model makes mistakes, read them before changing anything. Like a teacher marking a stack of tests, sort the wrong answers into piles: "misread the question", "never learned this topic", "answer key was wrong". The biggest pile tells you what to fix first.

The world also moves on. New customers, new products and new tricks mean the data a model sees next month is not quite the data it learned from. That is distribution shift, and the only defence is to keep watching the data and the results.

Mechanism

Error analysis means reading failures and grouping them. Pull 100 errors, tag each with a cause ("short text", "non-English", "label wrong", "new product"), and count. The biggest bucket tells you what to fix next. Also compute metrics per slice (segment of the data); an average can hide a group where the model fails badly.

Hyperparameters are settings chosen before training (learning rate, tree depth, regularisation strength). Tune them on the validation set only, using grid search, random search (usually better per trial), or Bayesian optimisation (Optuna). Use cross-validation when data is small. Touch the test set once.

Distribution shift is when production data differs from training data. Covariate shift: inputs change (new customer region). Label/prior shift: class balance changes (fraud spikes). Concept drift: the relationship itself changes (new fraud tactics). Detect it by monitoring input statistics and, when labels arrive, performance (17.7).

Example

A document classifier drops from 92% to 84% in March. Input monitoring shows the share of scanned PDFs rose from 5% to 30% after a new client onboarded; OCR text is noisy. Error analysis confirms 70% of new errors are scanned documents. Fix: improve OCR and add scanned samples to training, then add a "scanned" slice to the dashboard.

Laptop lab: tuning with Optuna Laptop · CPU
# pip install optuna
import optuna
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import cross_val_score
from sklearn.ensemble import HistGradientBoostingClassifier
X, y = load_breast_cancer(return_X_y=True)
def objective(t):
    m = HistGradientBoostingClassifier(learning_rate=t.suggest_float("lr", 0.01, 0.5, log=True),
                                       max_depth=t.suggest_int("depth", 2, 8), random_state=0)
    return cross_val_score(m, X, y, cv=5, scoring="f1").mean()
study = optuna.create_study(direction="maximize", sampler=optuna.samplers.TPESampler(seed=0))
study.optimize(objective, n_trials=30); print(study.best_params, round(study.best_value, 4))

The numbers

Counting causes. 100 wrong answers, each tagged with one cause:

CauseErrors
Scanned PDFs with noisy text45
Not in English25

Other10

Fixing scanned PDFs could remove up to 45% of the errors; a bigger model might remove a few of each.

Grid against random search. Trying 5 learning rates × 5 tree depths is 25 training runs, but tests only 5 different values of each setting. 25 random combinations test 25 different values of each, which is why random search usually finds a better setting for the same cost.

Shift, in numbers. In the example below, scanned PDFs went from 5% to 30% of incoming documents. If the model is 92% right on clean documents and 65% right on scanned ones, its overall accuracy falls from about 91% to about 84% without anything in the model changing.

Code

The program breaks the results on your example project’s table down by one column, to find where the model is weakest, then compares the first and last three months of data to look for drift. Change which months are compared (order[:3] and order[-3:]) and run it again.
