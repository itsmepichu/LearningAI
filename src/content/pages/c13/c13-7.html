Intuition

Six months after release someone asks: which data trained this model, with which settings, and how did it score? Without records, nobody knows, and nobody can rebuild it.

Experiment tracking records every run’s data version, code, configuration and results. A model registry keeps each released model as an unchangeable version linked to that run, and a model card tells users what it is for and where it fails.

Mechanism

  • Experiment tracking: every training run logs its config, code commit, dataset version, base model revision, hyperparameters, metrics curves, evaluation results and output artefacts (MLflow, Weights & Biases, or similar).
  • Versioning: datasets (DVC, lakeFS, Hugging Face dataset revisions) and models (a model registry with immutable versions and stages such as staging/production). A model version should be traceable back to exactly the data and code that produced it.
  • Reproducibility: pinned environments (container image digest), seeds, deterministic data ordering; record hardware. Exact bitwise reproduction on GPUs is often impossible; aim for "same metrics within tolerance".
  • Release criteria: pre-agreed gates (13.6 scorecard), a model card (intended use, training data summary, evaluation results, limitations, licence), approval by an owner, and a rollback plan (18.4).

Toolbox for model adaptation

PEFT
LoRA · adapters

LoRA and other adapter methods for any Transformers model; merge or hot-swap adapters.

TRL
SFT · DPO · GRPO

Trainers for each post-training stage, integrated with PEFT and quantisation.

Unsloth
fast LoRA/QLoRA on one GPU

Optimised kernels and ready notebooks for Colab/Kaggle; a good path for larger fine-tunes once you have done the 13.3 Colab guide, which takes the same steps by hand. GPU

Axolotl · torchtune
config-driven fine-tuning

Axolotl: YAML-configured SFT/DPO/QLoRA recipes including multi-GPU. torchtune is no longer actively maintained (development wound down in 2025), so prefer Axolotl, TRL or Unsloth for new work. GPU

Argilla · Label Studio
annotation · review

Labelling and expert-review UIs with agreement tracking; run locally with Docker or pip.

MLflow · DVC
tracking · registry · data versioning

Experiment tracking and model registry; Git-like versioning for datasets and pipelines.

The numbers

Hashes as fingerprints. A 12-character hash of the dataset changes completely if a single label changes, so "trained on dataset 2268…" names exactly one version.

Within tolerance. GPU training is rarely bit-for-bit repeatable. If the release run scored 0.964 and a rerun scores 0.961, the difference is 0.003, inside a tolerance of 0.005, so the run counts as reproduced. A rerun at 0.950 differs by 0.014 and does not.

Storage. 200 runs × a 40 MB adapter = 8 GB; 200 full 8B models in 16-bit would be 200 × 16 GB = 3.2 TB.

Code

The program hashes your project’s labelled data and a training config into a run id, shows that changing one label makes a new dataset version, checks a rerun against a tolerance and refuses to edit a registered version. Change the tolerance and run it again.

# pip install mlflow ; then run `mlflow ui` and open http://127.0.0.1:5000
import mlflow
mlflow.set_experiment("invoice-extractor")
with mlflow.start_run(run_name="lora-r8-lr2e-4"):
    mlflow.log_params({"base": "SmolLM2-135M-Instruct", "r": 8, "lr": 2e-4, "dataset": "invoices@v12"})
    # ... train ...
    mlflow.log_metrics({"field_acc": 0.964, "fabrication_rate": 0.021, "general_if": 0.785})
    mlflow.log_artifacts("lora-out", artifact_path="adapter")
