Create a release and handover package

  1. Write a release manifest binding code, prompts, tools, model, tokenizer, index and evaluation-suite versions.
  2. Run quality, security, latency and cost gates with explicit thresholds and critical blockers.
  3. Simulate shadow and canary stages, inject a quality regression, and restore the previous manifest.
  4. Write ownership, SLOs, dashboards, runbooks, data lifecycle, known limits and rollback steps.
Keep as evidenceA reviewable release package and a rollback drill report.
Pass conditionThe rollback restores a coherent, compatible system, verified by an end-to-end task.
