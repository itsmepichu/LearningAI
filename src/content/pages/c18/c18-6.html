Intuition

A system that learns from use needs a routine: collect feedback linked to the request, have people label a sample, keep evaluation data and training data apart, and decide in advance what should start a re-tune.

A retraining trigger is that decision written down, such as "2,000 new corrected examples" or "quality below target for 3 days". It opens a piece of work; it never ships anything by itself. And the full evaluation runs every week even when nothing changed, because the world under the system does.

Mechanism

  • Feedback collection: explicit (ratings with optional reason categories), implicit (rephrases, copy actions, escalations, edits to drafts: the diff between the AI draft and the sent version is excellent training signal), and outcome feedback joined later (17.7). Make feedback cheap for users and always link it to the trace.
  • Annotation: route sampled and flagged traces to reviewers with the guideline (13.2), building evaluation and training data continuously.
  • Retraining / re-tuning triggers: defined conditions, such as quality SLO breach for N days, drift metrics beyond threshold, enough new labelled data (e.g. +2,000 corrected examples), a new base model, or a policy change. Triggers open a work item; retraining still goes through all gates.
  • Scheduled re-evaluation: run the full suite on the production release weekly even without changes, because providers, documents and user behaviour change underneath you. Refresh the evaluation set itself quarterly with new production samples so it does not go stale.
Example: draft edits as signal

Support agents edit AI-drafted replies before sending. Logging (draft, sent) pairs with the edit distance gives an automatic quality metric (median edit fraction fell from 34% to 19% over two prompt versions) and, after review, a fine-tuning dataset of preferred replies, plus DPO pairs with the draft as "rejected" and the sent version as "chosen".

The numbers

Edits as a measurement. If an agent deletes 120 characters from a 300-character draft before sending, the edit fraction is 120 ÷ 300 = 40%. A new prompt that brings the median to 17% means agents rewrite far less.

When the trigger fires (illustrative). 50 corrected drafts a day reach 2,000 new examples in 2,000 ÷ 50 = 40 days. Splitting them 20% to evaluation and 80% to training keeps 400 for testing that the model never trains on.

Code

The program writes simulated reply drafts for your project’s messages under two prompt versions, measures how much agents edit before sending, and checks a retraining trigger. Make v13 as wordy as v12 and run it again.
