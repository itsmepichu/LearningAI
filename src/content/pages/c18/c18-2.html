• Reproducible builds: lockfiles, pinned base images by digest, pinned engine versions (vLLM, CUDA), deterministic container builds; the same commit produces the same image.
  • Infrastructure as code (IaC): GPU node pools, vector databases, queues, gateways, IAM, secrets references, dashboards and alerts are defined in code (OpenTofu/Terraform, Pulumi, Kubernetes manifests with Helm/Kustomize), reviewed and applied by pipelines, not clicked in consoles.
  • Environment promotion: dev → staging → production with the same artefacts (image digests, prompt versions, model IDs); only configuration differs. Staging mirrors production shape (same engine, same index type, a realistic data sample) so tests are meaningful.
  • GitOps: the desired state of each environment lives in a repository; a controller (Argo CD, Flux) syncs clusters to it, giving an audit trail and easy rollback by reverting a commit.
Example: GPU pool as code (OpenTofu/Terraform, illustrative)
module "llm_pool" {
  source        = "./modules/gpu-node-pool"
  name          = "answer-8b-fp8"
  gpu_type      = var.gpu_type            # per environment
  min_nodes     = var.env == "prod" ? 3 : 0
  max_nodes     = var.env == "prod" ? 24 : 2
  labels        = { workload = "interactive", model = "8b-fp8" }
  taints        = ["gpu=true:NoSchedule"]
}
