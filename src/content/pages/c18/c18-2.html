Intuition

If every kitchen in a restaurant chain cooked from memory, no two meals would match. Infrastructure as code writes the recipe down: GPU pools, databases, permissions and alerts are files that are reviewed and applied by a pipeline.

And the meal is cooked once. The artefact built and tested in staging is the very one that runs in production: environment promotion moves the same image digest forward and changes only configuration.

Mechanism

  • Reproducible builds: lockfiles, pinned base images by digest, pinned engine versions (vLLM, CUDA), deterministic container builds; the same commit produces the same image.
  • Infrastructure as code (IaC): GPU node pools, vector databases, queues, gateways, IAM, secrets references, dashboards and alerts are defined in code (OpenTofu/Terraform, Pulumi, Kubernetes manifests with Helm/Kustomize), reviewed and applied by pipelines, not clicked in consoles.
  • Environment promotion: dev → staging → production with the same artefacts (image digests, prompt versions, model IDs); only configuration differs. Staging mirrors production shape (same engine, same index type, a realistic data sample) so tests are meaningful.
  • GitOps: the desired state of each environment lives in a repository; a controller (Argo CD, Flux) syncs clusters to it, giving an audit trail and easy rollback by reverting a commit.
Example: GPU pool as code (OpenTofu/Terraform, illustrative)
module "llm_pool" {
  source        = "./modules/gpu-node-pool"
  name          = "answer-8b-fp8"
  gpu_type      = var.gpu_type            # per environment
  min_nodes     = var.env == "prod" ? 3 : 0
  max_nodes     = var.env == "prod" ? 24 : 2
  labels        = { workload = "interactive", model = "8b-fp8" }
  taints        = ["gpu=true:NoSchedule"]
}

The numbers

Unpinned dependencies drift (illustrative). If 40 dependencies are unpinned and each publishes a new release on average every 3 months, about 40 ÷ 90 ≈ 0.44 of them change on any given day. Rebuild a week later and about 3 dependencies are probably different from what you tested.

Rollback by commit. With GitOps, the previous state of production is one revert away; reapplying it takes as long as the sync, often a few minutes.

Code

The program builds an artefact from pinned inputs and promotes its digest through development, staging and production, then shows that rebuilding from unpinned inputs ships something staging never tested. Pin the second build’s inputs and run it again.
