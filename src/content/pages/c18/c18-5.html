Intuition

A new model version is like a new colleague taking over a job: probably capable, but with different habits. It may write longer answers, follow the JSON format less strictly, refuse more often, or count tokens differently.

So a model upgrade is a release, not a setting. Run the suite with the current prompts to see the raw difference, re-tune the prompts, check the properties your code depends on, then shadow, canary and keep the old route until the rollback window has passed.

Mechanism

Models change more often than most dependencies: new versions every few months, deprecations with fixed retirement dates, behaviour changes inside a version alias. Treat each as a release:

  • Inventory and deprecation tracking: which features use which model versions; provider retirement dates on a calendar with owners.
  • Compatibility testing: run the full suite with the new model and the current prompts, then with re-tuned prompts. Check structured-output adherence, tool-calling format, refusal behaviour, verbosity (output tokens change cost and latency), tokenizer differences (context budgets, 7.3), and supported parameters (some models ignore temperature or require different settings).
  • Prompt portability: prompts tuned for one model often underperform on another; budget time to re-tune, and keep model-specific prompt variants versioned together.
  • Embedding migrations: full re-embed with blue/green indexes (10.7); queries and documents must switch embedding models atomically.
  • Fine-tuned models: a new base model means re-running fine-tuning and all of 13.6.

Example: an alias that moved

A team called a provider's "latest" model alias. When the provider pointed it at a new version, median output length rose 38% and JSON adherence fell slightly, so cost rose and a parser started failing on 0.7% of requests. Pinning dated snapshot versions, plus the weekly scheduled re-evaluation (18.6), turns such changes into planned upgrades instead of surprises.

The numbers

Longer answers cost money (illustrative). If median output grows from 220 to 305 tokens, that is 85 more tokens a request. At 3 million requests a month and 15 dollars per million output tokens: 85 × 3,000,000 × 15 ÷ 1,000,000 ≈ 3,800 dollars a month more.

Small format changes break code. JSON adherence falling from 99.8% to 99.1% sounds tiny, but at 3 million requests it is 0.7% × 3,000,000 = 21,000 more parser failures a month.
