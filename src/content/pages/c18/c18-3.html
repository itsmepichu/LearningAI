Intuition

A release gate is a turnstile that only opens when a change has shown its ticket: quality at least as good as before, no new safety failures, latency and cost within limits. It applies to every change, including a one-line prompt edit.

Each gate catches different mistakes. A tighter prompt may pass quality and fail cost; a cheaper model may pass cost and fail quality; a new tool may pass both and fail security. That is why all four run.

Mechanism

A gate is an automated check that blocks promotion when a threshold is not met. Gates make the acceptance criteria of 8.1 and the release criteria of 13.7 enforceable for every change.

GateChecksExample threshold
QualityRegression suite, critical set, per-segment scores, judge-based metrics with CIsNo critical case regresses; overall ≥ baseline − 0.5 pts (within CI); no language drops > 2 pts
Safety / securityInjection and jailbreak suites, isolation tests, secret scanning, dependency and model scans0 cross-tenant leaks; injection success rate ≤ baseline; no critical CVEs

CostTokens per task on the eval suite × prices; projected monthly costCost per successful task ≤ +10% vs current release unless approved

The numbers

Averages hide segments (illustrative). A suite of 400 cases in 6 segments passes 92% before and 91.8% after a change, which looks fine.

  • But one segment of 26 cases fell from 92% to 77%: 4 more failures in that segment, hidden by the other 374.
  • A rule "no segment drops more than 3 points" fails this change, as it should.

Critical cases. If 1 in 10 cases is tagged critical, 40 cases must never regress, whatever the overall score.

Code

The program builds a suite from your project’s labelled data, runs a baseline and a candidate that is worse on one segment, and fails the gate on the overall rate, regressed critical cases or a segment drop. Change MAX_SEGMENT_DROP and run it again.

Laptop lab: a quality gate in CI Laptop · CPU (runner) · or GitHub Actions
# .github/workflows/eval.yml (sketch) — runs promptfoo against a model endpoint on every PR touching prompts/
on: {pull_request: {paths: ["prompts/**", "promptfooconfig.yaml"]}}
jobs:
  eval:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npx promptfoo@latest eval -c promptfooconfig.yaml -o results.json
        env: {OPENAI_API_KEY: "${{ secrets.EVAL_API_KEY }}"}     # or point providers at a hosted test endpoint
      - run: python scripts/gate.py results.json --min-pass-rate 0.95 --critical-tag critical

gate.py is 20 lines: load results, compute pass rate overall and on cases tagged critical, exit non-zero if below thresholds. Locally you can run the same command against Ollama before pushing.
