Intuition

Training is walking downhill in the dark, and the optimiser is your walking style. Plain gradient descent takes each step based only on the slope under your feet. Momentum is like a rolling ball: it builds up speed in a steady direction and is not thrown off by small bumps. Adam adjusts the step size for every direction separately, so it takes careful steps where the ground is steep and bigger ones where it is flat.

The schedule is the pace: start gently while you get your bearings (warm-up), walk briskly, then slow down as you get close so you do not overshoot the bottom.

Mechanism

Batch: the group of examples used for one gradient estimate. Step (iteration): one weight update. Epoch: one full pass over the training data.
SGD: plain stochastic gradient descent on mini-batches. Momentum: keep a running average of gradients so steps accelerate in consistent directions.
Adam / AdamW: adapts the step size per parameter using running averages of the gradient (first moment) and squared gradient (second moment). AdamW decouples weight decay. It is the default for transformers. It stores two extra numbers per parameter, which matters for memory (6.6).
Schedule: changing the learning rate over training. Standard for LLMs: linear warm-up from near zero for the first few hundred or thousand steps, then cosine decay to a small final value.

Batch size trades noise for cost. Small batches give noisy gradients (which can help escape poor regions) but use hardware poorly. Large batches give smoother gradients and better throughput but may need a larger learning rate and warm-up. When memory limits the batch, gradient accumulation sums gradients over several small batches before one update, simulating a larger batch.

Example: LoRA fine-tuning settings

A typical small fine-tuning run: AdamW, peak learning rate 2×10⁻⁴, 3% warm-up, cosine decay, effective batch 32 (batch 4 × 8 accumulation steps), 2–3 epochs over 5,000 examples. If validation loss starts rising in epoch 3 while training loss keeps falling, stop at epoch 2 (early stopping).

The numbers

Steps per epoch. 10,000 examples in batches of 32 is 10,000 ÷ 32 ≈ 313 steps per epoch. Three epochs is about 940 updates.

Gradient accumulation. If only 4 examples fit on the GPU, adding up the gradients of 8 small batches before each update acts like one batch of 4 × 8 = 32.

Adam’s memory. Adam keeps two extra numbers for every parameter. For an 8-billion-parameter model stored in 4-byte numbers, that is 8 billion × 2 × 4 bytes = 64 GB, on top of the weights and gradients.

Warm-up, in numbers. With a peak learning rate of 0.0003 and 100 warm-up steps, step 50 uses half the peak (0.00015), step 100 reaches the peak, and from there a cosine curve slowly lowers it towards a small final value.

Code

The program runs plain gradient descent, momentum and Adam for 60 steps down a long, narrow valley and prints how close each one gets to the bottom, then prints the learning rate of a warm-up and cosine schedule. Try a plain SGD learning rate of 0.08, or change WARMUP, and run it again.
