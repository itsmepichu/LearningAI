Batch: the group of examples used for one gradient estimate. Step (iteration): one weight update. Epoch: one full pass over the training data.
SGD: plain stochastic gradient descent on mini-batches. Momentum: keep a running average of gradients so steps accelerate in consistent directions.
Adam / AdamW: adapts the step size per parameter using running averages of the gradient (first moment) and squared gradient (second moment). AdamW decouples weight decay. It is the default for transformers. It stores two extra numbers per parameter, which matters for memory (6.6).
Schedule: changing the learning rate over training. Standard for LLMs: linear warm-up from near zero for the first few hundred or thousand steps, then cosine decay to a small final value.

Batch size trades noise for cost. Small batches give noisy gradients (which can help escape poor regions) but use hardware poorly. Large batches give smoother gradients and better throughput but may need a larger learning rate and warm-up. When memory limits the batch, gradient accumulation sums gradients over several small batches before one update, simulating a larger batch.

Example: LoRA fine-tuning settings

A typical small fine-tuning run: AdamW, peak learning rate 2×10⁻⁴, 3% warm-up, cosine decay, effective batch 32 (batch 4 × 8 accumulation steps), 2–3 epochs over 5,000 examples. If validation loss starts rising in epoch 3 while training loss keeps falling, stop at epoch 2 (early stopping).
