The classic "golden signals" still apply: latency, traffic, errors and saturation. For AI services, measure them per stage and per model.

  • Latency percentiles: report p50, p95, p99, never only the mean. LLM latency distributions are skewed; the mean hides the slow tail that users complain about. Track TTFT, ITL and total time separately (14.2), and per-step durations for agents.
  • Errors: by type (timeouts, 429 rate limits, 5xx, schema-validation failures, tool errors, content-filter blocks). A rise in validation failures is often the first sign of a model change.
  • Saturation: GPU KV-cache usage, running/waiting sequences, provider rate-limit headroom, connection pool use, index node memory.
  • Queue depth and age: number of waiting items and age of the oldest one, for ingestion, agent tasks and request queues. Age is the better alert signal: it directly measures delay.
  • Availability: successful requests ÷ valid requests, against the SLO (15.2).
Example: an early warning

p50 latency is flat, but p99 climbs from 6 s to 19 s over an hour while the waiting-sequences gauge on one model replica rises. A long-context tenant has started sending 100k-token prompts that occupy KV cache. Admission limits per tenant (15.5) and a separate long-context pool resolve it.
