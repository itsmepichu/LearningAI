• Quality drift: scores decline gradually as user behaviour, products and documents change (3.6). Detect with continuous sampled evaluation and input-distribution monitoring (topics, languages, query lengths, retrieval score distributions).
  • Data freshness: track ingestion lag and index staleness against the freshness SLO (10.4), plus "answers citing documents older than X" for time-sensitive domains.
  • Model changes: providers update models behind aliases, deprecate versions, and change safety filters. Pin snapshot versions where offered, record the response's model version in every trace, and annotate dashboards when it changes. Re-run regression suites on any change (18.5).
  • Delayed feedback: the outcomes that matter (was the claim correct? did the customer churn? did the code cause an incident?) arrive days or months later. Join them back to the original trace by ID, and use faster proxy signals (17.4) in the meantime; validate that proxies track the real outcomes.
Example: joining delayed outcomes

A claims-triage model's "auto-approve" decisions are audited 45 days later. Each audit result is written with the original trace_id, so weekly reports show audited accuracy per prompt version and model version, revealing that the v14 prompt (released 6 weeks ago) has 3× the overturn rate of v13, which faster signals had not shown.
