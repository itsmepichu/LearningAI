Intuition

A shared phone bill is easy to pay and hard to explain. Cost attribution itemises it: every model call carries tags for the tenant, the feature, the user and the prompt version, and its token counts come from the provider’s response.

Then spend can be grouped any way you need, and surprises have names: one tenant calling an endpoint on every page view, or one feature whose outputs grew longer after a prompt change.

Mechanism

  • Token accounting: record input, cached input, output and reasoning tokens per call (from the provider response, not estimates), with model and price version.
  • Cost attribution: tag every call with tenant, user (or hashed ID), feature, environment and prompt version, so cost can be grouped any way. Include non-token costs (embeddings, vector DB, GPU-hours, tool APIs) allocated by usage.
  • GPU utilisation (self-hosted): tokens/s per GPU, KV usage, batch size, MFU/bandwidth utilisation (14.7), idle hours; cost per million tokens actually served.
  • Tenant-level usage: usage vs quota and contract, for billing, abuse detection and capacity forecasts (15.9).

The numbers

One call from the usage record, at illustrative prices of 3 dollars per million input tokens, 0.30 for cached input and 15 for output.

  • Uncached input: 5,120 − 4,096 = 1,024 tokens × 3 ÷ 1,000,000 ≈ 0.0031 dollars.
  • Cached input: 4,096 × 0.30 ÷ 1,000,000 ≈ 0.0012 dollars.
  • Output: 388 × 15 ÷ 1,000,000 ≈ 0.0058 dollars.
  • Total about 0.010 dollars; output is more than half of it, though it is under a tenth of the tokens.

Code

The program creates usage records tagged with a tenant and a grouping taken from your project’s data, prices their tokens and groups the spend by tenant, by that grouping and by token type. Raise the output price and run it again.
