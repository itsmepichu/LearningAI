Semantic conventions are agreed names and meanings for telemetry attributes, so tools from different vendors understand your data. The GenAI semantic conventions define spans, metrics and events for model calls, agents and tools. As of this writing (checked November 2026), they are marked Development status (not stable) and are now maintained in a dedicated repository, open-telemetry/semantic-conventions-genai; the old pages on opentelemetry.io point there.

ElementExamples (names as of the current draft; verify before use)
Span nameschat {model}, embeddings {model}, execute_tool {tool}, invoke_agent {agent}
Required/recommended attributesgen_ai.operation.name, gen_ai.provider.name, gen_ai.request.model, gen_ai.response.model, gen_ai.response.id, gen_ai.response.finish_reasons, gen_ai.usage.input_tokens, gen_ai.usage.output_tokens, gen_ai.request.temperature, gen_ai.request.max_tokens, gen_ai.conversation.id
Opt-in contentgen_ai.input.messages, gen_ai.output.messages, gen_ai.system_instructions, gen_ai.tool.definitions (sensitive; off by default)
Metricsgen_ai.client.token.usage, gen_ai.client.operation.duration, gen_ai.server.time_to_first_token, gen_ai.server.time_per_output_token
Other areasAgent spans, MCP conventions, provider-specific pages, events and exceptions

"Development" status means names and structure can change in breaking ways. Some attributes have already been renamed (for example, an older gen_ai.system attribute was superseded by gen_ai.provider.name, and per-message events moved towards message attributes). Some instrumentation libraries gate the newest experimental behaviour behind the OTEL_SEMCONV_STABILITY_OPT_IN environment variable; check each library's README for the values it supports.

In practice · HarborHarbor records which instrumentation version and convention revision emitted each trace, and tests dashboards against old and new attribute names before upgrading.
Failure to avoidAssuming the GenAI conventions are stable because OpenTelemetry itself is mature.
